# 模板缩略图优化方案

## 现状问题（页面打开慢的根因）

- **学员奖状生成器**：模板选择列表的 16 个小缩略图（`TemplateThumbnail` 组件）全部用 `new Image()` 加载**原图**（横版 3508×2480、734KB–1.7MB），首次打开页面约下载 **19MB**。
- **案例图片生成器**：模板网格 `<img>` 加载 `previewUrl`，而 manifest 里 `previewFilename === filename`，即 5 张 1.0–1.2MB 的原始 PNG（约 **5.5MB**）。
- **生成记录小图**：两个工具的历史记录小图（56px 网格 / h-44 卡片）也在加载七牛全尺寸 PNG。
- 实时预览和下载**必须继续用原图**（高清导出），不动；只有"模板选择展示"换成缩略图。

manifest 的 `previewFilename` 字段和 API route 的 `previewUrl` 是现成入口，无需改案例图客户端代码。

## 实施步骤

### 1. 缩略图生成脚本（新文件 `prisma/generateTemplateThumbnails.ts`）

仿照 `prisma/*.ts` 现有 tsx 脚本模式，用项目已有的 `@napi-rs/canvas`：
- `public/student-certificate-templates/*.{jpg,png,webp}` → 最长边缩到 480px，JPEG 质量 80，输出到 `public/student-certificate-templates/thumbs/<同名>.jpg`（16 张，预计每张 30–80KB）。
- `public/case-image-templates/*.png` → 最长边缩到 960px，**先铺白底再画图**（避免透明区域变黑），JPEG 质量 80，输出为同目录平铺文件 `<名>-thumb.jpg`（API route 的 `publicTemplateUrl` 用 `path.basename()`，不支持子目录）。
- 幂等可重复执行，供以后新增模板时重新生成。

### 2. 案例图片生成器

- 更新 `public/case-image-templates/manifest.json`：5 个模板的 `previewFilename` 指向 `-thumb.jpg`。路由已支持 `previewUrl ≠ url`，**客户端网格零改动**；画布渲染仍用 `url` 原图。
- "生成预览"占位区也用 `previewUrl`（960px 缩略图在 max-h-420 显示仍然清晰，可接受）。

### 3. 学员奖状生成器

- **schema**：`StudentCertificateTemplate` 加 `thumbnailPath String?`；新建迁移（ALTER TABLE + 回填：非 `upload-` 的内置模板 `thumbnailPath = '/student-certificate-templates/thumbs/' || 文件名`）；`npm run db:generate`。
- **`src/lib/student-certificate-template-files.ts`**：加 `certificateThumbnailPathFor(backgroundPath)` 帮助函数（内置图 → `thumbs/<同名>.jpg`；上传图 → `thumbs/<同名>.jpg`）。
- **`src/lib/student-certificate-templates.ts`** 序列化时输出 `thumbnailUrl`：有 `thumbnailPath` 用之；内置图回退用静态路径；上传图回退用 `/api/.../background?variant=thumb`（保持原图的权限门控模式一致）。
- **`CertificateTemplate` 类型**（config.ts）加 `thumbnailUrl: string`。
- **`StudentCertificateClient.tsx`**：`TemplateThumbnail` 的 `image.src` 改为 `template.thumbnailUrl`。实时预览/大图/下载仍用 `backgroundUrl` 原图，导出质量不变。
- **底图 API route**（`[id]/background/route.ts`）：支持 `?variant=thumb`，返回 `thumbnailPath` 文件（不存在时回退原图）。
- **上传 route**：保存原图后用 `@napi-rs/canvas` 生成缩略图写入 `thumbs/`，并返回 `thumbnailPath`。
- **Server Actions**：create/update 时由服务端根据 `backgroundPath` 用帮助函数计算 `thumbnailPath` 落库（不改 action 入参签名）；换图时同步更新。
- 更新 `public/student-certificate-templates/README.md` 说明 thumbs 约定。

### 4. 生成记录小图（七牛 imageView2）

- `src/lib/qiniu.ts` 的 `generateCaseImagePrivateUrl` 加 `thumbnailWidth?: number` 选项：在**签名前**把 `&imageView2/2/w/<宽>` 拼进 URL（与现有 `response-content-type` 同一模式，私有 bucket 支持签名后处理参数）。
- 两个记录序列化器（`case-image-records.ts`、`student-certificate-records.ts`）的 DTO 增加 `thumbnailUrl`（案例图 w=400、奖状 w=640）。
- 两个客户端的历史记录小图 `<img>` 改用 `thumbnailUrl`；查看大图/下载仍用原 `imageUrl`/`imageDownloadUrl`。admin 端不动。

## 验证

1. `npm run db:generate` + `npx tsc --noEmit` 通过；脚本生成的 thumbs 用 `ls -lh` 确认体积（整体 < 1.5MB）。
2. curl 一个带 `imageView2` 的签名 URL 确认七牛正常处理（若 bucket 不支持则记录小图回退原图，不影响模板缩略图主目标）。
3. `npm run dev` 打开两个工具页，Network 面板确认模板列表只加载 thumbs、无 1MB+ 原图请求；选中模板后实时预览/下载导出仍为高清。

## 效果预期

- 学员奖状页首屏模板流量 **~19MB → <1.5MB**（原图仅在选中模板时加载 1 张，用于高清预览/导出）。
- 案例图片页首屏模板流量 **~5.5MB → ~0.5MB**。
- 历史记录小图从全尺寸 PNG 降为 400/640px 缩放图。
