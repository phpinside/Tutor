# 统一登录与账号迁移

统一入口为 `/auth/login`，支持手机号或原管理员账号。登录页不要求选择身份。原 `/admin/login`、`/operator/login` 和三组登录/退出 API 均接入统一流程。

## 账号与权限

- `Account`：全局唯一登录标识、统一密码、账号启用状态、默认及上次工作台。
- `AccountRole`：教练、学管、运营、超级管理员的角色授权。
- `Teacher.accountId` / `Operator.accountId`：已经验证的业务档案关联。邀请白名单中的“本人教练身份”也使用该关联。
- `AuthSession`：数据库保存令牌摘要，浏览器仅持有随机令牌。切换工作台轮换令牌；退出撤销当前设备会话并删除旧身份 Cookie；修改/重置密码撤销所有设备会话。
- `AuthRateLimit`：PostgreSQL 原子计数，多实例和所有旧登录接口共享限流。

每次请求检查账号、角色授权、学管启用状态、教练入驻限制。教练入驻限制只影响教练角色。角色被撤销时原工作台会话失效，用户重新登录后可进入其余可用工作台。

跳转顺序为：有权限的站内业务链接 → 上次工作台 → 默认工作台 → 可用角色兜底。管理角色不会因权限较高而自动优先。外部地址、转义路径和认证回环地址不能作为登录目标。

`src/lib/auth/session.ts` 提供统一会话；`src/lib/auth/compat.ts` 为存量业务提供服务端派生身份，只兼容读取，不接受旧身份 Cookie。新增代码直接使用统一会话及权限方法。Prisma 业务查询默认省略教练和学管密码字段，认证代码显式请求哈希。

认证 API 的同源校验、Middleware 和 Route Handler 的绝对跳转、邀请链接统一通过 `src/lib/request-url.ts`，使用 `X-Forwarded-Host`（缺省时使用 `Host`）和 `X-Forwarded-Proto` 还原当前请求的公网来源。无需配置 `NEXT_PUBLIC_APP_URL`，旧配置不再影响这些地址；快捷登录助手的脚本地址也使用浏览器当前来源。这样避免 HTTPS 反向代理后的内部监听地址导致误报 403 或跳转至 `localhost`。Caddy/Nginx 等入口代理必须覆盖客户端传入的这两个转发头；来源仍需精确匹配协议、域名和端口，并拒绝跨站请求。

## 上线顺序

1. 备份业务数据库：`npm run db:backup`。保留当前部署版本，安排短维护窗口。
2. 执行迁移：`npx prisma migrate deploy`，再运行 `npm run db:generate`。不要在生产使用 `db:push`。本次迁移仅新增表、索引和可空关联，不删除业务记录或密码。
3. 运行 `npm run db:accounts` 只读检查账号。输出重复档案 ID、脱敏手机号及统计，不输出密码。确认结果后可运行 `npm run db:accounts -- --apply`，批量迁移无冲突账号；也可保留首次登录自动迁移。
4. 确认 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD_HASH`（或 `ADMIN_PASSWORD`）已配置。管理员首次成功登录迁入数据库，此后以数据库统一密码为准。未配置凭据时不会启用默认口令。管理员用户名不能与教练/学管手机号冲突。
5. 发布新版本。所有旧身份 Cookie 均不再作为认证依据，现有用户需要重新登录。
6. 验证教练、学管、运营、管理员登录、业务链接回跳、角色切换、禁用、退出及密码重置。

首次迁移保留原单角色密码哈希。手机号同时存在于两份存量档案时，不自动合并；首次登录验证两套原密码后关联，之后统一使用上方“密码”字段所填的密码。无法验证时管理员应先核验真实归属，再分别重置两份存量档案的密码，用户完成关联。不能把重置同一号码的两份账号当作归属证明。

公开注册只授予教练角色。已有学管/运营账号可在登录后从“账号设置 → 申请教练工作台”补建教练档案，并验证当前密码。管理员新增学管/运营时，若已有统一账号则显式增加角色并保留原密码；若存在未迁移教练档案则保留双方验证流程。

管理员重置已关联档案时修改的是统一密码。学管不能通过重置教练密码接管其关联的管理账号；此类账号由超级管理员处理。本人改密在 `/account` 校验原密码后完成。忘记密码入口说明人工核验流程，不发送短信。

登录手机号不能通过普通教练资料编辑修改。外部学管同步改号时会同步已关联账号与本人教练档案，遇到其他账号占用则报冲突，不合并权限，并撤销旧会话。

## 验证

单元测试：`npm run test:auth`（未显式配置专用测试环境时跳过 HTTP 集成测试）。

HTTP 集成测试必须使用独立本地 PostgreSQL 数据库，库名以 `tutor_auth_test` 开头。准备完整 schema，并启动指向该库的 Next.js 服务；测试服务器管理员凭据通过环境变量独立提供。调用示例：

```bash
AUTH_TEST_DATABASE_URL='postgresql://test_user@127.0.0.1:55439/tutor_auth_test' \
AUTH_TEST_BASE_URL='http://127.0.0.1:3108' \
AUTH_TEST_ADMIN_LOGIN='auth-test-admin' \
AUTH_TEST_ADMIN_PASSWORD="$AUTH_TEST_ADMIN_PASSWORD" npm run test:auth
```

集成测试创建并清理专用测试档案，覆盖自动识别、关联验证、越权拒绝、会话轮换、即时禁用、改密撤销、邀请注册、旧接口兼容和跨入口限流。禁止将测试服务连接到业务数据库。

## 回退

发布失败时回退应用前先评估旧版本认证风险。新增表可保留，业务档案旧密码字段在统一改密时仍同步维护，因此无需通过删除新表回退。数据库备份是最终恢复依据。旧身份 Cookie 的信任逻辑不应恢复到新版本。
